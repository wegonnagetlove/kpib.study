# Перенос рабочего стола 104 КПИБ в Timeweb Cloud

Целевой проект Timeweb Cloud: **3197373** (https://timeweb.cloud/my/projects/3197373).

## Источник

- Репозиторий: `wegonnagetlove/kpib.study` (https://github.com/wegonnagetlove/kpib.study).
- Ветка: `main`.
- Тип приложения: **Frontend → HTML/CSS/JS**.
- Путь до директории проекта: корень репозитория (`/`, без подпапки).
- Сборка и команда запуска не требуются. `index.html` и все статические ресурсы уже находятся в корне.
- Не требуется перенос базы данных: рейтинг, расписание, материалы, объявления, документы и ссылки находятся в `data/`, `content/`, `assets/`, `brs/` и `calendar.ics`.

## Развертывание в проекте 3197373

1. Открыть проект 3197373 и создать приложение в **App Platform** с привязкой именно к этому проекту.
2. Подключить репозиторий `wegonnagetlove/kpib.study` через GitHub или по HTTPS-ссылке.
3. Выбрать `main`, тип `HTML/CSS/JS`, статические файлы в корне репозитория.
4. Запустить первый деплой и записать **ID приложения** и технический публичный адрес с вкладки «Дашборд». ID приложения не равен ID проекта 3197373.
5. Проверить главную страницу, `#/m/15`, рейтинги, `#/schedule`, `#/calc`, материалы, `calendar.ics` и загрузку файлов (включая PDF и PPT).

## Автоматическое развертывание и ссылки в уведомлениях

Если репозиторий подключен в Timeweb **по URL**, автодеплой может быть недоступен. Для его запуска в GitHub Actions используется `.github/workflows/timeweb.yml`.

В настройках GitHub репозитория **Settings → Secrets and variables → Actions** задать:

- **Secret `TIMEWEB_TOKEN`**: токен API Timeweb Cloud. Никогда не помещать токен в код, лог или этот документ.
- **Variable `TIMEWEB_APP_ID`**: ID созданного в проекте 3197373 приложения, **не 3197373**. Устаревшее значение `290299` удалено как небезопасное значение по умолчанию.
- **Variable `SITE_URL`**: технический адрес сайта в Timeweb или подключенный собственный домен, с завершающим `/`.

После этого push в `main` или ручной запуск workflow «Деплой на Timeweb» инициирует деплой. Для GitHub Actions workflow «Уведомления и календарь» `SITE_URL` применяется к push-уведомлениям и ссылкам календарных событий. Кнопка подписки на календарь на сайте формирует ссылку из фактического адреса открытого сайта.

## Важно проверить

- Смена домена **не переносит автоматически localStorage** из браузеров пользователей: выбор себя, тема оформления, отметки прочитанного и сохраненные записи на новом домене задаются заново.
- Старые ссылки `tatnet.app` не начнут переадресовываться автоматически. Перенаправление настраивается на стороне действующего адреса/домена, если есть доступ к его управлению.
- Синхронизация Craft, БРС, расписания МГУ и Telegram выполняется через **GitHub Actions** и продолжает работать с репозиторием. Для корректной работы требуются существующие секреты и права GitHub Actions.
- Репозиторий и статические данные сейчас **публичные**. Если необходимо ограничить доступ к персональным данным и оценкам, требуется отдельное проектирование авторизации и защищенного хранения: статический хостинг сам по себе не ограничивает чтение `data/*.json` и `data/brs/*.csv`.
- Нельзя считать перенос завершенным без успешного деплоя, публичного URL нового приложения и проверки разделов.
